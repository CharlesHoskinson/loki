## Best-practice requirements (with sources)
1. SemVer. Cargo's compatibility guide (https://doc.rust-lang.org/cargo/reference/semver.html): adding public items is a minor change; adding a Cargo feature is minor if it is not on `default`; removing a feature is major; changing `default` to drop a feature is major; adding a dependency is minor unless it breaks users. Pre-1.0 `0.y.z` lets y be the major number. A fork that adds features and changes no existing item is a MINOR change under 0.x.y terms, but the version must differ from upstream 0.8.3 to publish.
2. Mechanical semver gate: cargo-semver-checks (https://github.com/obi1kenobi/cargo-semver-checks). It lints API changes before `cargo publish`; exit 100 = violation, 101 = could not run. Its README says it checks all features by default, and it does not flag default-feature changes. It has a known gap for feature subsets. So it does not replace the compatibility gate; the stock test (tests-stock/, loki-harness/) still does.
3. MSRV. Cargo's rust-version (https://doc.rust-lang.org/cargo/reference/rust-version.html): Cargo refuses to build on a toolchain below rust-version and applies to all targets (examples, tests, benches). Decide one value (1.76.0 manifest vs 1.90 changelog) and add a CI job that builds with it. Measure the real MSRV before setting it.
4. Changelog. Keep a Changelog 1.1.0 (https://keepachangelog.com/en/1.1.0/): latest first, dated, grouped as Added, Changed, Deprecated, Removed, Fixed, Security. Loki entries belong under [Unreleased] and the release.
5. Advisories. RustSec (https://rustsec.org/): the advisory database is kept by the Rust Secure Code Working Group, and cargo-audit scans Cargo.lock against it. cargo-deny covers advisories, bans, licenses and sources (https://embarkstudios.github.io/cargo-deny/); deny.toml is the config file (the page says `cargo deny init` writes a default config, but I did not confirm the file name from the page itself).
6. SBOM. CycloneDX Rust tooling: cargo-cyclonedx writes a bom.xml per Cargo.toml and honors enabled features (repo https://github.com/Shnatsel/cyclonedx-rust-cargo ; Cargo-based SPDX alternative: cargo-sbom). The release should pin the tool version. Current version is unverified.
7. crates.io. Publishing is permanent: "The version can never be overwritten, and the code cannot be deleted," and taken crate names cannot be reused (https://doc.rust-lang.org/cargo/reference/publishing.html). Yank does not delete code. Required fields: license, description, repository, readme. The `.crate` file limit is 10 MB. A fork can only publish under a new name or a new version; name ownership must be checked before publish.
8. Licence provenance. Dual licence at top level, Apache-2.0 for loki-gpu. A release needs a NOTICE/provenance statement that names the upstream source (midnight-proofs 0.8.3 is MIT OR Apache-2.0), the PSE halo2/Zcash lineage (README.md:260), and the clean-room status of loki-gpu.
