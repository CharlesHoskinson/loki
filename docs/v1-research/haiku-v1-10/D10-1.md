## Best practice (sources)
1. Feature-gated items: `#![cfg_attr(docsrs, feature(doc_cfg))]` plus `#[cfg_attr(docsrs, doc(cfg(feature = "x")))]` shows "requires feature" badges on docs.rs. doc_cfg is unstable; the example needs `#![feature(doc_cfg)]`, tracking issue #43781. Source: https://doc.rust-lang.org/unstable-book/language-features/doc-cfg.html . The rustdoc attribute page is https://doc.rust-lang.org/rustdoc/write-documentation/the-doc-attribute.html but it does not cover doc(cfg) (checked).
2. Keep one feature table, generated or checked against Cargo.toml, so README.md:94-127, ARCHITECTURE.md:242 and modules/README.md do not drift. Standard practice here is a CI check that every `[features]` key appears in the README table (not verified against an external source; proposal).
3. WASM docs: state the target triple, the threading mode (single-thread vs wasm-threads), the required cross-origin isolation headers, and the nightly requirement. Source: https://github.com/RReverser/wasm-bindgen-rayon (requires nightly, `+atomics,+bulk-memory`, COOP/COEP for SharedArrayBuffer). Rayon's WASM note: https://github.com/rayon-rs/rayon#usage-with-webassembly (cited by README.md:260; not fetched here).
4. Mobile docs: list the exact Rust targets and their install status. Installed here: aarch64-apple-ios, aarch64-apple-ios-sim, aarch64-linux-android, wasm32-unknown-unknown (`rustup target list --installed`, run on this host). x86_64-linux-android is available, not installed.
5. Changelog: Keep a Changelog 1.1.0 (https://keepachangelog.com/en/1.1.0/). Sections: Added, Changed, Deprecated, Removed, Fixed, Security. Loki's [Unreleased] at CHANGELOG.md:8 is empty.
6. Identity and claims: docs/brand/IDENTITY.md already limits "same proof" to tested fixtures. Keep that wording in release docs.
