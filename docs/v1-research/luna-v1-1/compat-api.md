## External practice and references

- [`cargo-semver-checks` README](https://docs.rs/crate/cargo-semver-checks/latest/source/README.md): supports an explicit `--baseline-root` or `--baseline-rustdoc` for an unpublished/current crate. It analyzes Rust API compatibility but documents rustdoc JSON/toolchain constraints and notes it does not catch every semver violation. Whether a same-version 0.8.3 baseline root is accepted as intended remains unverified; CI must smoke-test the exact command and fall back to stock-generated rustdoc JSON if needed. Use an explicit stock root/checksum, pin checker and Rust toolchain, and do not use it as the only gate.
- [`cargo-public-api` README](https://github.com/cargo-public-api/cargo-public-api): lists and diffs Rust public API items, including `cargo public-api diff <version>`. It uses rustdoc JSON and currently requires a recent nightly for generating it. Because the stock and Loki manifests both say version 0.8.3, generate item listings from each source root and directly compare them rather than assuming the version-keyed diff selects the stock registry artifact. Pin the checker/nightly pair separately from product MSRV.
- [Cargo Book: Features](https://doc.rust-lang.org/cargo/reference/features.html): documents defaults, implicit optional-dependency feature names, feature unification, additive-feature guidance, and the semver significance of default-feature changes. Compare the full manifest/feature graph; a default-only API build or `--all-features` is insufficient.
- [Cargo Book: Rust version field](https://doc.rust-lang.org/cargo/reference/manifest.html#the-rust-version-field) and [Rust platform support](https://doc.rust-lang.org/rustc/platform-support.html): the package's declared MSRV and target support must be built/recorded separately; tooling that needs a newer nightly must not silently raise the crate's MSRV.

## Proposed compatibility gate

Owned change: `v1-compat-api-contract`.

- Pin stock 0.8.3 registry source by checksum `19b2e4b1acb581ad741b0cb7c0e9dbdf51142f4e9518886f25fcff40a6702dcc`; do not patch or replace the stock oracle.
- Run public API + Cargo feature/default comparisons over the explicit supported feature × cfg/target matrix. Allow additive Loki items, reject stock removals/signature or trait changes, keep every Loki behavior opt-in, and name each unsupported feature/target combination with an owner and reason.
- Preserve Rust 1.76 and edition 2021. Keep checker/nightly toolchain pinned separately.
- Build exact `=0.8.3` and caret `^0.8` clean downstream `[patch.crates-io]` consumers against the same local/git Loki package version 0.8.3, and use an unpatched registry control to prove the oracle remains independent. These are source-resolution checks, not duplicate crate publication.
- Require stock/Loki proof verification in both directions and existing key/SRS serialization checks. Extend shared compat-proof coverage to public PK serialization where supported.
- Run API/default jobs on native CPU, wasm32, iOS device/simulator, and Android; consume platform-owned WASM browser/Node single/threads and mobile emulator/device runtime/size/memory contracts. GPU features stay out of CPU lanes.
- Product release tag is v1.0.0; the patched crate retains package name/version `midnight-proofs` 0.8.3. Do not publish a different package identity without product-owner approval.
