## Cross-area fixture contract

Proposed canonical bundle root: `loki-harness/fixtures/v1/`; index: `manifest.jsonl`; transcript vectors: `transcripts/<transcript_vector_id>.jsonl`. Each fixture row carries schema version, stable fixture ID, stock version and source pin, Loki revision, circuit ID, k, instance mode, batch shape, `SerdeFormat`, transcript mode, lookup-placement-order mode, worker schedule, feature set, seed ID, expected outcome, transcript vector ID, relative artifact paths, and SHA-256 digests. Artifacts cover SRS/verifier parameters, VK, PK, proof, public inputs, and explicit valid/negative variants. Transcript vectors contain ordered event identities and bytes, plus challenge labels and bytes; do not include witnesses. Transcript/challenge equality claims require a matched lookup-placement order and worker schedule; randomized lookup cases are judged by cross-acceptance and key identity.

Target teams agreed on target-native stock 0.8.3 and Loki verification in both proof directions; a native stock verifier is additional evidence, not a substitute for WASM/mobile runs. Perf's Sherlock leaf/parent/decider fixture origin remains perf-owned; reuse the manifest schema and verifier oracle, without claiming those chain fixtures exist in compat-proof.

The final scout review is recorded at [cp-final.md](/home/charles/repos/loki-wt/v1/docs/v1-research/haiku-v1-2/cp-final.md). Its findings drove these changes: requirements name the two exact `Fixture` forms; W2 explicitly lists one to three proofs and zero to two committed columns; transcript challenges are compared against stock-generated vectors only under matched lookup-order/worker conditions; k20 uses a dedicated serial runner without the existing 292-second wrapper; stock-matrix cites the 32-line differential test correctly, names the 0.8.1 source URL, and points to stock's 0.8.3 `InvalidInstances` guard. Both split changes pass strict validation after those edits.

## Outside best practice and primary sources

- [Project Wycheproof format and JSON schemas](https://github.com/C2SP/wycheproof/blob/main/doc/index.md): use explicit valid/invalid/acceptable vectors with stable case IDs and schema validation for cryptographic negative cases. Wycheproof does not itself cover PLONK proof interoperability; adapt the vector discipline, not its algorithm coverage.
- [Vega Prover transcript schedule](https://microsoft.github.io/vega-prover/spec/transcript-schedule.html): specify the exact ordered absorb/squeeze/domain-separation operations and byte encodings. This supports keeping transcript event order and challenge vectors separate and reviewable.
- [ark-transcript API documentation](https://docs.rs/ark-transcript/latest/ark_transcript/struct.Transcript.html): transcript framing and separation behavior are concrete byte-level rules, so record them in fixtures rather than relying on a high-level “same hash” assertion.
- [Ethereum execution-specs external KZG vectors](https://steel.ethereum.foundation/docs/execution-specs/tests/cancun/eip4844_blobs/test_point_evaluation_precompile/test_external_vectors/): cross-implementation vectors are useful for KZG components, but do not establish PLONK proof compatibility. Record origin/revision for any reused external vectors.

Scout also identified Trail of Bits Decree's transcript uniqueness checks at [trailofbits/decree](https://github.com/trailofbits/decree). This is a supplementary tool source rather than an independent protocol standard; use it only if its transcript model fits the existing API.
