## 1. Lean proof validation (sorry and axioms)

- Lean Language Reference, Validating Proofs: https://lean-lang.org/doc/reference/latest/ValidatingProofs/
  - `#print axioms` lists transitive axioms. The expected built-in set is `propext`, `Classical.choice`, `Quot.sound`. `sorryAx` means the theorem or a dependency is incomplete. Axioms with `_native` in their names mean native evaluation.
  - The reference explicitly recommends CI only for **lean4checker** ("We recommend running lean4checker as part of CI..."). The `#print axioms` and `sorryAx` checks are described as manual steps, not CI requirements.
  - `lake build +Module` with no errors or warnings is a build-level check CI can run.
  - `lake comparator` with external checkers is recommended only for high-risk settings.
  - Search snippet: older reference versions (4.27 to 4.29) said `#print axioms` did not work inside a module; 4.30 and 4.31 drop that note. Loki pins v4.34.1, so this caveat should not apply, but verify on the pinned toolchain.
- axiom-audit: https://github.com/leanprover-community/axiom-audit
  - Fetched. Fails CI if any declaration transitively depends on an axiom outside an allowlist. Inspects the kernel environment, so it catches `sorryAx`, `native_decide` (`Lean.ofReduceBool`) and custom axioms that a grep cannot see.
  - Default allowlist is `propext`, `Classical.choice`, `Quot.sound`. Overridable with `--allow`. Also `--root`, `--modules`, `--modules-from`, `--json`.
  - Run as `lake exe axiom-audit` (or `lake env axiom-audit`) after building.
  - Exit codes: 0 clean, 1 violation or nothing audited, 2 usage or IO error. Nothing audited = failure, which guards against an empty root.
- lean-action: https://github.com/leanprover/lean-action (search snippet; the search result URL was a dependabot mirror, `github-redirect.dependabot.com/leanprover/lean-action`, so re-check against the canonical repo before pinning).
  - Inputs include `lean4checker: true` (per the reference above), a Mathlib cache option, and `lint-module` for `lake exe runLinter`, which requires Batteries downstream. Search snippet only; no sorry-specific input was found.

**Actionable for v1 (Loki's `lean_action_ci.yml` runs only lake build and docgen):**
1. Add `lean4checker: true` to the existing `leanprover/lean-action@v1` step (reference recommendation).
2. Add an axiom-audit job: `lake build` then `lake exe axiom-audit --allow propext,Classical.choice,Quot.sound` over the `LokiLean` lib. This replaces the manual `GATE-AXIOMS` block in `AUDIT.md`, which is regenerated by hand via `scripts/audit_gen.py` (see `~/repos/loki-lean/AUDIT.md:514-732`). It also catches `sorryAx` in `BackendMsm`/`BackendQuotient` if they land on the release branch.
3. Keep `sorryAx` out of the allowlist so an open `OBLIGATION` fails CI. If the owner wants open obligations on `main` in the interim, use an explicit, reviewed exception list in the allow flag rather than widening the default.
4. Add a `drift.py` exit-0 job only after the citation tree guesses are fixed (see `lean2-gates.md`, 353 guessed trees).

## 2. Rust public API compatibility (semver and API diff)

- cargo-semver-checks: https://github.com/obi1kenobi/cargo-semver-checks
  - Fetched. Baseline options: default crates.io previous version, `--baseline-version`, `--baseline-rev`, `--baseline-root`, `--baseline-rustdoc`. Custom registries are not supported (issue #160).
  - Exit: 0 no deny-level violations, 100 violations, 101 check could not complete.
  - GitHub Action: `obi1kenobi/cargo-semver-checks-action@v2`. Default uses latest tool and stable Rust.
  - **Stated limitations (primary):** does not catch breaking changes to field or parameter types, generics or lifetimes, or breaking changes that appear only with a subset of features.
- Search snippets (not opened): zerocopy pinned nightly because a new nightly broke cargo-semver-checks; tokio uses the tool directly rather than the action; maintainers say it is "necessary but not sufficient". Source URLs: https://redirect.github.com/google/zerocopy/pull/753 and https://predr.ag/blog/semver-violations-are-common-better-tooling-is-the-answer/ (both search results only).

**Implication for Loki's requirement (superset of stock 0.8.3, feature flags, signatures):** cargo-semver-checks alone is not enough. Its own README says it misses field and parameter type changes, generics and lifetimes, and feature-subset breaks, and Loki's compat claim covers exactly those. Use it as one gate, plus a public-API diff of the rustdoc JSON (or `cargo public-api`, not yet checked in a primary source) run per feature subset against stock 0.8.3. The baseline is the `midnight-proofs` crate, so `--baseline-version 0.8.3` requires the package name to match, or a `--baseline-rustdoc` file built from `~/.cargo/registry/src/*/midnight-proofs-0.8.3`.
