# Review: GPU and prover novelty

## Concerns

- `README.md:21,40` and `docs/GPU.md:13-15` describe acceptance by stock `midnight-proofs` 0.8.3 as both a contract and a working result. Loki's evidence is in `LOKI-GPU-MSM.md:121-134`: a CUDA-required k8 proof was accepted by an independent crates.io 0.8.3 verifier, and the verifier rejected a changed public input. This establishes the result for that fixture. It does not establish novelty for GPU-accelerated Halo2/KZG proving generally. Axiom's public [`halo2-gpu`](https://github.com/axiom-crypto/halo2-gpu) README describes a CUDA-accelerated Halo2 prover, identifies PSE's KZG-backed fork as its ancestor, and credits sppark MSM kernels. Ingonyama's [`halo2` fork](https://github.com/ingonyama-zk/halo2) describes an ICICLE CUDA integration of ezkl-Halo2. [PSE-Halo2](https://github.com/privacy-ethereum/halo2) documents its KZG backend. Limit novelty language to the exact target and evidence. Do not claim Loki is the first GPU Halo2/KZG prover.

- `README.md:26` and `docs/GPU.md:7-9` describe CUDA MSM and NTT paths based on sppark. The underlying primitives predate Loki: [sppark](https://github.com/supranational/sppark) provides CUDA MSM and NTT templates, including BLS12-381. `LOKI-GPU-MSM.md:5-16,121-134` documents Loki's adapter and integration into `midnight-proofs` 0.8.3, including checked conversions, dispatch, fallback and stock-verifier evidence. ICICLE is another GPU-acceleration library, and Ingonyama publishes a Halo2 integration ([ICICLE](https://github.com/ingonyama-zk/icicle), [Ingonyama Halo2](https://github.com/ingonyama-zk/halo2)). Neither project should be described as absent prior art. `LOKI-GPU-MSM.md:15` says ICICLE was not attempted, so this work cannot support a comparative performance claim.

- zkSync and Scroll are relevant to broad GPU-prover novelty. The sources checked do not describe the exact Midnight prover target. Matter Labs describes [`era-bellman-cuda`](https://github.com/matter-labs/era-bellman-cuda) as GPU-accelerated cryptographic functionality for the zkSync prover; the page does not describe a Midnight/Halo2 0.8.3 backend. Scroll's archived [`scroll-prover`](https://github.com/scroll-tech/scroll-prover) documents a multi-level KZG proving system and verifier generation, but does not document GPU integration. Its current [E2E guide](https://github.com/scroll-tech/scroll/blob/develop/docs/testing/docker-compose-e2e-guide.md) calls the GPU prover a zkVM prover. These projects rule out broad GPU-ZK-prover novelty, but do not answer whether a prior implementation had the exact compatibility described here.

- Axiom's `halo2-axiom-gpu` is the closest public comparison found. Its [workspace manifest](https://github.com/axiom-crypto/halo2-gpu/blob/main/Cargo.toml) and [crate manifest](https://github.com/axiom-crypto/halo2-gpu/blob/main/halo2_proofs/Cargo.toml) describe a CUDA-accelerated KZG prover on BN254, with package `halo2-axiom-gpu`, `halo2-axiom` 0.5.3 and `halo2curves-axiom` 0.7.3 with `bn256-table`. Ingonyama's [crate manifest](https://github.com/ingonyama-zk/halo2/blob/main/halo2_proofs/Cargo.toml) names package `halo2_proofs` 0.3.0 and dependency `icicle-bn254`; its [README](https://github.com/ingonyama-zk/halo2/blob/main/README.md) describes a CUDA ICICLE integration fork of ezkl-Halo2. These are strong prior examples of GPU Halo2 proving. Both manifests name BN254. This repository's `Cargo.toml` declares `midnight-proofs` 0.8.3 and its source and docs identify BLS12-381 as the accelerated target. The curve difference makes the implementations distinct, but still related.

- `README.md:52-54` reports a 19.2% reduction for W10's A3 parent prove-and-verify measurement. The README also identifies it as one matched sample on a branch outside the cited main commit. `docs/GPU.md:68-71` likewise marks W10 as branch-only. This is a project measurement. It does not establish novelty or a general recursion-chain speedup. Keep the result's scope, sample count and branch status with the number. A novelty claim about this measurement would also need its source design record and a comparable prior-art search. Do not describe this A3 parent sample as a complete recursion-chain result.

- `README.md:28,51` names root-product division as a Loki change. `LOKI-MULTIOPEN.md:204-208` says run 2 ports the KZG division from midnight-zk PR #565; lines 210-219 describe the product polynomial operation. Attribute the algorithm to that upstream work. `LOKI-MULTIOPEN.md:339-347` records Loki's implementation results: run 2 has 4.25% / 4.43% phase reductions with mixed end-to-end changes. The serial comparison has 12.83% / 19.00% lower phase time and 2.74% lower / 0.11% higher end-to-end time. The note says these samples do not establish a speedup.

## Questions

- Is the novelty scope limited to integration with the exact `midnight-proofs` 0.8.3 / BLS12-381 target? The sources reviewed describe related Halo2 CUDA proving, but do not establish byte-compatible output for the unmodified Midnight 0.8.3 verifier. A completed comparison could support a narrowly stated engineering result.
- Does the W10 design record define its 294.3 s and 237.8 s measurements as one A3 parent prove-and-verify job, or as a complete recursion chain? The public README describes an A3 parent result. Keep it separate from a full-chain latency claim unless the raw record shows otherwise.
- Is there a public implementation or paper measuring Sherlock-style recursive-chain latency on the same circuit family? This review found no source supporting priority for that exact workload. The search does not establish that no such source exists.

## Suggestions

- In the lead-owned novelty document, describe the evidenced result: Loki integrates CUDA MSM/NTT paths into the `midnight-proofs` 0.8.3 BLS12-381 prover, and a CUDA-required proof fixture was accepted by an unmodified 0.8.3 verifier. Cite the fixture and independent verifier setup in `LOKI-GPU-MSM.md:121-134`. Axiom, ICICLE-Halo2 and sppark establish prior GPU Halo2 proving or arithmetic primitives, so avoid a general first-GPU-Halo2 claim.
- State target- and version-level priority only after checking the source tree, license and output compatibility of each close prior project. If that comparison remains incomplete, keep the claim in TODO. The public sources reviewed establish related prior work but do not resolve the exact Midnight compatibility question.
- Present W10's 19.2% as a branch-specific, single-sample result. Include its raw source, measured scope, baseline and sample count. Do not present it as novelty evidence or a stable speedup.
- Attribute root-product division to the midnight-zk PR #565 port. Report Loki's implementation and measured behavior separately, including run 2's variable results and end-to-end changes.

## Novelty evidence

Public prior art rules out the broad claim "a GPU-accelerated Halo2/KZG prover." Axiom publishes a CUDA-enabled Halo2 prover descended from the PSE KZG-backed branch and using sppark MSM primitives. Ingonyama publishes an ICICLE CUDA integration fork of ezkl-Halo2. PSE-Halo2 documents its KZG backend. Sppark provides CUDA MSM and NTT templates for ZK workloads and BLS12-381. zkSync publishes a GPU cryptography library for its prover. Scroll's archived prover documents multi-level KZG proving, and its newer E2E path describes a GPU-enabled zkVM prover. The sources reviewed do not show that these projects target Midnight's exact 0.8.3 crate or pass its unmodified verifier.

Loki's documented result is narrower: this repository uses package name and version `midnight-proofs` 0.8.3 and targets BLS12-381 (`Cargo.toml:12-16`; `src/poly/kzg/msm/cuda.rs:1`). It reports a CUDA-required proof generated by the `cuda` feature and accepted by an independent stock `midnight-proofs = 0.8.3` verifier. Changing the public input causes rejection (`LOKI-GPU-MSM.md:121-134`). The published [midnight-proofs 0.8.3 crate page](https://docs.rs/crate/midnight-proofs/0.8.3) also lists version 0.8.3 and its `midnight-curves` dependency. This documents compatibility for the reported fixture. Axiom and Ingonyama establish related GPU Halo2 prior art on BN254. The sources reviewed do not establish an earlier GPU-enabled `midnight-proofs` 0.8.3 BLS12-381 build with stock-verifier compatibility. Describe Loki's result relative to those different targets. Do not claim global priority: this source review is not an exhaustive patent or publication search, and W10's single observation does not establish a general recursion-chain improvement.

The root-product algorithm is attributed to midnight-zk PR #565 (`LOKI-MULTIOPEN.md:204-219`), so it is not a Loki invention. Loki's contribution is the feature-gated implementation in this prover and its recorded proof and phase results. Run 2 has mixed end-to-end measurements, and the note says the small differences are not established (`LOKI-MULTIOPEN.md:339-347`).
