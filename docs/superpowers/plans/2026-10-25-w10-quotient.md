# W10 GPU numerator implementation plan

**Goal:** accelerate the largest measured named A3 phase without changing the numerator at any extended coset index or the stock proof/verifier contract.

**Prerequisite:** finish the queued sequential H0 A3 CPU/GPU measurements and confirm the target. Exploratory real A3 profiles identify quotient evaluation as largest (CPU 72.882 s; GPU-feature run 58.340 s). Those overlapping, pre-H0 results do not establish GPU use or a speedup.

**Architecture:** compile the existing GraphEvaluator calculations and explicit permutation/lookup/trash formulas into a straight-line field program in the existing term order. Run a row interpreter with a bounded scratch tile, using the existing sppark BLS12-381 scalar field and natural-order NTT. Advice/instance and argument coefficient columns are padded, coset-scaled and transformed on the device, then remain resident through numerator evaluation. Read-only PK cosets are uploaded once per invocation. Multiply the numerator by the CPU domain's precomputed zero-skipping vanishing inverses and perform inverse NTT/coset recovery before downloading coefficients. A test output mode downloads the raw numerator instead.

**Alternatives:** full-vector intermediate operations require storage proportional to all rows times all nodes; a CPU-only fused loop does not meet the requested device evaluation. Choose the bounded interpreter. Do not change term order, circuit degree, VK, SRS or transcript behavior.

**Constraints:** new behavior only under `cuda-quotient`; no changes to default arithmetic. Stay in W10 and commit via the host runner. Four Cargo build jobs. Serialize heavy proofs with the host GPU lock. No private fields, transcripts, witnesses or coordinates in diagnostics. Do not modify Moriarty sources. The feature can select the CPU path for unsupported fields/capacity, but must expose that outcome and never pass a GPU gate via fallback.

## Design review resolutions

- One synchronous resident invocation owns all device buffers and acquires the W9 shared runtime guard exactly once. Internal NTT calls operate on device pointers/that invocation's stream; they must not call the public host-slice adapter or reacquire its guard. Complete copies, kernels and recovery before returning; buffers remain live until synchronization, then release on every path.
- Budget every uploaded PK coset, every live coefficient/argument column, output, NTT workspace and interpreter scratch against current free memory, reserving 2 GiB. Cap scratch at 256 MiB and reduce its warp-aligned tile size to fit the instruction count. If the complete resident set does not fit, select an explicitly counted CPU capacity fallback before allocation; the GPU acceptance gate must reject that fallback. Keep PK host columns and all advice/instance coefficients alive for subsequent evaluations/openings.
- Regression cases must carry the accumulator across two or more instances, consume `PreviousValue` in custom gates, place permutation boundary/link terms before all recurrence terms, continue `current_delta` across sets, and include an uneven final set. Preserve zero-part Horner behavior and graph intermediate targets.
- Recovery repeats the short inverse table by the global coset index, includes exactly one inverse-NTT normalization, and scales coefficient j by `ZETA^(-j)`. Check division and recovery separately before testing their composition. Artificial zero entries check zero-preserving implementation agreement, not the nonzero-coset hypothesis of Lean's quotient theorem.
- Use distinct numerator-evaluation/recovered-coefficient variants. Both variants must converge on the existing truncation, `(domain.n-1)` limb splitting, blinding and commitment tail; do not reinterpret its stock limb size. CPU and GPU paths retain the original trace coefficients for later openings.
