# Spec Delta

## Purpose

Keeps Loki usable as a drop-in, additive replacement for stock `midnight-proofs` 0.8.3 across its Rust API, Cargo feature interface, default build, and supported CPU targets.

## ADDED Requirements

### Requirement: Stock public API remains available

Loki SHALL preserve every public item, signature, trait implementation contract, and target-gated public item exposed by stock `midnight-proofs` 0.8.3, while allowing additive Loki API.

#### Scenario: Release API surface has no stock removals
- **WHEN** `scripts/compat-api/check.sh --baseline-stock 0.8.3` compares item listings generated by `cargo public-api` from the pinned stock and Loki source roots and runs `cargo semver-checks` against that stock baseline for every supported feature/cfg/target row
- **THEN** no stock 0.8.3 item, signature, or trait contract is removed or changed, additions are recorded separately, and the checksum of the exact registry baseline is in the report. The baseline API is exported through `src/lib.rs:20-30` and its public modules.

#### Scenario: Unsupported feature and target combinations are explicit
- **WHEN** CI compares the tested matrix in `scripts/compat-api/check.sh` with Cargo metadata and `cargo tree -e features`
- **THEN** every stock-supported feature and target combination is checked; any omitted stock row first reproduces the same unsupported/failure result with unmodified stock 0.8.3 and records its oracle output, while a required stock-supported row cannot be waived by an owner. No combination is silently skipped. Loki-only unsupported combinations are separately identified. Existing feature gates and the mutually exclusive backend compile error are `Cargo.toml:45-74` and `src/lib.rs:11-18`.

### Requirement: Stock Cargo features remain selectable

Loki SHALL retain every stock 0.8.3 feature name, implicit optional-dependency feature, dependency-feature relationship, and build effect, including `committed-instances`, `circuit-params`, `derive_serde`, `dev-curves`, `truncated-challenges`, `bench-internal`, and implicit `criterion` and `tabbycat` features.

#### Scenario: Upstream feature requests resolve unchanged
- **WHEN** `scripts/compat-api/check-features.sh` compares Cargo metadata against the checksum-pinned stock manifest and runs `cargo check --locked --no-default-features --features "$STOCK_FEATURES"` for each supported stock feature combination
- **THEN** each stock feature name resolves and enables the same stock functionality, with no missing feature or substituted behavior. The baseline feature declarations are `Cargo.toml:45-58` and stock registry `Cargo.toml.orig` under `~/.cargo/registry/src/*/midnight-proofs-0.8.3`.

### Requirement: Stock defaults and Loki opt-ins remain isolated

Loki SHALL keep the stock default feature set exactly `committed-instances` and SHALL keep every Loki-only behavior disabled unless its Loki feature is explicitly enabled.

#### Scenario: Default build matches stock behavior
- **WHEN** CI runs `cargo test --locked --test backend_default_stock` with default features and `cargo tree -e features -i midnight-proofs`
- **THEN** the default set is exactly `committed-instances`, no Loki-only feature is active, and the default behavior checks match stock for their covered lookup, MSM, and domain cases. The existing anchors are `Cargo.toml:45-74` and `tests/backend_default_stock.rs:1-74,140-180`.

#### Scenario: Loki behavior requires explicit opt-in
- **WHEN** CI runs the default-feature test above and inspects every Loki feature-gated public module and code path
- **THEN** no Loki-only behavior activates by default, while explicit feature selection remains available. The current feature-gated surfaces are anchored at `src/lib.rs:20-26` and `Cargo.toml:59-74`.

### Requirement: Stock package and compiler contracts remain usable

Loki SHALL retain stock's package name and version identity, Rust 2021 edition, and Rust 1.76.0 minimum supported Rust version. If any of these contracts is removed or a target is excluded, the release SHALL NOT claim full stock compatibility.

#### Scenario: Declared compiler and package metadata match stock
- **WHEN** CI runs `cargo +1.76.0 check --locked --manifest-path compat/msrv/Cargo.toml` using a dedicated lock that resolves only Rust-1.76-compatible dependency releases, then parses `cargo metadata --no-deps --format-version 1` and compares it with stock
- **THEN** the package remains `midnight-proofs` 0.8.3, edition 2021, and Rust 1.76.0, the MSRV-resolved CPU build succeeds, and the product's main lockfile is not silently represented as MSRV-compatible if its locked dependencies are not. The existing metadata anchors are `Cargo.toml:12-16`; current dependency constraints include `rayon = "1.10"` at `Cargo.toml:184-185`.

### Requirement: Crates.io patch remains a drop-in dependency

Loki SHALL resolve through a downstream `[patch.crates-io]` entry without requiring downstream source-import, package-name, or dependency-version changes.

#### Scenario: Exact and caret downstream dependencies select Loki
- **WHEN** CI runs `cargo check --locked --manifest-path compat/consumer-exact/Cargo.toml` with `midnight-proofs = "=0.8.3"` and `cargo check --locked --manifest-path compat/consumer-caret/Cargo.toml` with `midnight-proofs = "^0.8"`, each using `[patch.crates-io]`
- **THEN** both clean consumers resolve to Loki without source import or dependency edits and compile a stock API call. The patch route and caret requirement are documented at `README.md:81-92`.

### Requirement: CPU target compatibility is checked on release targets

The compatibility gate SHALL compile the stock-default API and downstream consumer for native CPU, `wasm32-unknown-unknown`, `aarch64-apple-ios`, `aarch64-apple-ios-sim`, and `aarch64-linux-android`; WASM runner behavior, thread modes, and platform budgets SHALL use the contracts owned by the WASM and mobile areas.

#### Scenario: API and stock oracle run on each CPU target
- **WHEN** `scripts/compat-api/check.sh --target "$TARGET"` builds the consumer and public API listing for native, `wasm32-unknown-unknown`, `aarch64-apple-ios`, `aarch64-apple-ios-sim`, and `aarch64-linux-android`, and `scripts/compat-api/check-platforms.sh` invokes platform-owned commands to execute Loki and unmodified stock 0.8.3 prover/verifier fixtures on browser/Node single-threaded and wasm-threads lanes plus iOS simulator and Android emulator using cases in `loki-harness/fixtures/v1/manifest.jsonl`
- **THEN** both verifiers accept both prover outputs for compat-proof-owned cases, supported VK/PK/SRS serialization round-trips match the compat-proof-owned manifest deliverable, failures block release, and named WASM/mobile runners have frozen numeric size/memory budgets. Stock 0.8.3 currently has no target-gated public items; per-target API listings confirm that while builds exercise target compatibility. Existing target anchors are `docs/PLATFORMS.md:311-327,349-358` and `TODO.md:295-307`; target entropy config is present in stock `Cargo.toml:172-174` and Loki `Cargo.toml:227-229`; the cited pointer-width cfgs are tests, at `src/plonk/evaluation.rs:855-856` and `src/poly/domain.rs:721-722`; serialization APIs are `src/plonk/mod.rs:95-223,372-457`.

### Requirement: Default-on prover changes preserve stock results

Loki SHALL inventory every default-on algorithm change against stock 0.8.3 and preserve the stock observable result for controlled fixtures independent of Rayon worker count.

#### Scenario: Default-on code deltas match the stock oracle
- **WHEN** `scripts/compat-api/check-default-deltas.sh` runs stock/Loki differential fixtures with controlled randomness, lookup-placement order, and worker schedules at `RAYON_NUM_THREADS=1`, `2`, and `20`, the higher of the perf-owned matched worker budgets (`v1-perf-benchmarks/design.md:19`)
- **THEN** the committed inventory names each default-on delta against stock, explicitly including permutation products (`src/plonk/permutation/prover.rs:107-145`) and lookup products/order (`src/plonk/lookup/prover.rs:198-231,391,549`), and compares arithmetic results at all three worker counts. It requires transcript/proof byte equality only for compat-proof-controlled deterministic fixtures with matched lookup order and worker schedule; randomized lookup-placement byte differences are diagnostic, while bidirectional stock acceptance remains mandatory for supported fixtures. The command emits `artifacts/compat-api/default-deltas/<source-sha>.json`; until this source-pinned artifact records all required rows as passing, the default-on delta gate is NOT QUALIFIED and blocks release. The remaining changed-path anchors are `src/poly/mod.rs:290-316`, `src/poly/domain.rs:267,296,356,412-422`, and `src/utils/arithmetic.rs:171-205`; fixture order and byte-equality limits are owned by `v1-compat-proof-wire-matrix/design.md:24-25`.

### Requirement: Wire-divergent opt-ins have separate compatibility claims

Each Loki-only feature SHALL be classified as API-only, execution-only, failure-semantic, or wire-divergent, and a wire-divergent opt-in SHALL be documented as outside stock byte-equality claims while retaining its own stock-verifier acceptance gate where it produces proofs.

#### Scenario: Opt-in compatibility claims are explicit
- **WHEN** `scripts/compat-api/check-features.sh` evaluates the per-feature compatibility ledger and runs the listed stock 0.8.3 verifier cases for proof-producing opt-ins
- **THEN** no wire-divergent feature is described as byte-identical to stock, every proof-producing opt-in accepted for v1 is empirically accepted by unmodified stock on its owned fixtures, its default-off status remains explicit, and any completeness claim remains a separate Lean obligation (including `TODO.md:51-53` for deterministic lookup order). Existing feature declarations are `Cargo.toml:59-74`; deterministic lookup's proof-byte divergence is `src/plonk/lookup/prover.rs:424-435`.

### Requirement: Compatibility evidence is published with the release

The v1 release SHALL publish the exact baseline, commands, target results, public API diff, feature diff, consumer result, and stock-oracle behavior evidence for its release commit.

#### Scenario: Release record proves the selected compatibility contract
- **WHEN** release CI runs `scripts/compat-api/check.sh`, both patched consumers, `cargo test --locked --test backend_default_stock`, `./loki-harness/run.sh`, and `scripts/compat-api/check-platforms.sh`
- **THEN** all gates and the registry checksum are attached to the product v1.0.0 release commit while the patched crate remains package `midnight-proofs` version 0.8.3; any failed, unrun, or unsupported shape remains a release blocker or a separately approved compat-proof decision. Existing behavior evidence and known gaps are `loki-harness/README.md:3-19,21-58` and `TODO.md:11-20`.
