# Design

## Context

See proposal.md for the release gap. The current native harness records one cold sample per backend, with Loki first (`loki-harness/README.md:64-69`). Existing Sherlock A3 timings are single samples and not a full chain (`docs/GPU.md:431-455`). Current W3 and W11 reports distinguish phase/synthetic improvements from end-to-end claims (`LOKI-CPU.md:105-124`, `LOKI-MULTIOPEN.md:76-85`). W12 is the Moriarty A3 residual branch `loki/w12-a3-residual` at `e50b775c3c7e9ebd77ec31c5337bb94d604b1957`, in `/home/charles/repos/loki-wt/w12-a3-residual`; it makes no changes to `loki-proofs` (`LOKI-A3-RESIDUAL.md:3-17`). It includes parent fast-path and PK reuse experiments; disk loading lost to setup and was not adopted (`LOKI-A3-RESIDUAL.md:19-27`). Its phase table is branch evidence (`LOKI-A3-RESIDUAL.md:73-90`), while the architecture page still calls chain cache savings an estimate (`docs/ARCHITECTURE.md:343`).

## Goals / Non-Goals

**Goals:** Define a matched, repeatable, independently verified head-to-head protocol; give the full leaf-parent-decider chain priority; attribute measured CPU phases; establish one stable native regression baseline; publish sufficient raw evidence to reproduce the v1 table.

**Non-Goals:** Change prover behavior, choose optimization winners, promise a speedup, duplicate platform owners' compile/compatibility gates, or require accelerator availability for CPU-only targets.

## Decisions

1. **Use the compat-proof fixture contract as the workload source.** Each fixture is identified by a stable ID and content digest. The compat-proof area owns the shared manifest schema, stock 0.8.3 pinning, and oracle commands. Perf owns availability of a full four-stage Sherlock chain fixture family and the smaller `sherlock-recursion-chain-smoke-v1` workload in that schema, with Moriarty circuit/source SHA and generated artifact digests pinned; do not create a second serializer or claim that compat-proof already supplies the chain workload. The smoke fixture qualifies CPU-only native and WASM runtime/budget rows; larger production-chain runs record an explicit timeout or unsupported-size outcome where a target cannot run them.
2. **Run stock and Loki as separate, unmodified timed processes.** Build a stock-only timing executable against only registry `midnight-proofs =0.8.3` and a Loki-only executable with locked dependencies; do not link both prover implementations into either timed process. Record commit, lockfile digest, feature list, compiler, and build profile. Never patch the stock verifier. Default workload families use stock defaults and Loki defaults. Sherlock and ZSWAP use the same `circuit-params` feature across all arms and must be disclosed as circuit-family rows; this is an explicit exception, not pure-default coverage. Loki-only rows are explicitly labeled opt-in experiments. This avoids treating the current mixed `loki-harness` single cold sample as an independent stock baseline (`loki-harness/README.md:64-69`, `wiki-llm/loki/benchmark/SUITE.md:56-72`).
3. **Measure chain boundaries separately.** Exclude one-time fixture/SRS/VK initialization from operational latency, but publish it separately. Preserve recurring request preparation, guards, PK construction, proving, interstage transport, semantic checks, and stock verification within the applicable operational and chain intervals. Record leaf A102, leaf A80, parent A3, and decider stages; `chain_ms` spans the four serial stages and independent receipts. Report `create_proof_ms`, operational proving, operational prove-plus-stock-verify, chain time, setup, and verification counts as distinct metrics. Record W3/W11 phase intervals inside proving time; record W12 A3 residual-path measurements as a separately pinned experiment, including any PK-cache probe as test-only unless adopted.
4. **Pair and alternate executions.** Follow the accepted benchmark suite's frozen row manifest and block policy. Measure five same-seed process-cold A3 pilot runs per primary arm/budget; proceed only when `(max-min)/median ≤5%`. For CHAIN, retain ten independent process-cold→process-warm blocks per arm and CPU budget, with balanced shuffled arm order. Report median, IQR, min, max, and every observation; do not make a small-sample bootstrap significance claim. A baseline is frozen for an identified source/fixture/toolchain tuple. A new tuple needs a new baseline and does not overwrite history.
5. **Apply a numeric native regression decision.** Use the pinned, reserved native host with matched CPU masks/workers at N=4 and N=20 and require the accepted suite's idle, memory, and noise qualification. After the baseline tuple is frozen, fail the regression gate if Loki median `chain_ms` is more than 5% slower than matched stock for either required CPU budget; a result at or below 5% passes this timing decision. Also fail closed on missing samples, failed correctness receipts, or an unqualified host. This operational threshold does not claim statistical significance from small n. Shared runners and unqualified aarch64/WASM/mobile/GPU rows remain informational for stock-relative speed. Cross-target compatibility and numeric memory/size/time budgets remain mandatory in their platform CI; perf consumes their valid measurements.
6. **Keep CPU and accelerator measurements distinct.** GPU event time, transfer time, fallback, setup, proof verification, CPU phases, and chain latency remain separate fields. No kernel result stands in for a chain result. W3 and W11 use named CPU phases; W12 A3 residual phase measurements are separately pinned experimental rows, and its test-only PK disk probe is never mislabeled as production cache behavior.
7. **Treat publication as a checked evidence bundle.** `RESULTS.md` is the human-readable closing table. Every row links to machine-readable raw samples and the exact runner command. The validator rejects missing source pins, fixture IDs, sample counts, verifier outcomes, or claims that blur historical and current results. Missing historical artifacts are listed as unavailable rather than reconstructed from memory.

No specific host profile is established by the cited accepted SUITE passages. Astra's assigned host owner must name and qualify the reserved native CPU host, exact CPU masks, toolchain, memory, OS, and (for GPU rows) GPU details in the frozen baseline manifest before regression gating. The suite's cited N=4/N=20 and noise protocol inform methodology, not machine identity or qualification. WASM and mobile compatibility/budget rows are maintained by their target owners, with CPU-only gates that do not require CUDA. The `compat-proof` owner supplies portable fixture schemas, including `sherlock-recursion-chain-smoke-v1`; perf consumes the canonical manifest and records measured results and any timeout/unsupported-size outcome. These are planned interfaces, not evidence that fixtures, runners, or measurements already exist.

Alternatives considered: Criterion-only microbenchmarks are not sufficient because they do not cover the recursion chain or compare an independent stock binary; a single end-to-end timer loses the required W3/W11/W12 attribution; a broad matrix of mandatory runners would make the gate fragile and conflate platform availability with performance quality; small-sample significance tests and confidence intervals were rejected by the accepted suite in favor of full raw samples plus median/IQR/min/max reporting.

## Risks / Trade-offs

- [Runner drift or noisy neighbors] → Gate only on the reserved host after the suite's idle/memory/noise qualifications; preserve every block and fail closed on invalid measurements.
- [Different code paths or random behavior between builds] → Pin identical fixtures, parameters, worker counts, defaults, and record all opt-in feature differences; use verifier acceptance rather than requiring proof-byte identity where the stock algorithm is nondeterministic.
- [Instrumentation changes timing] → Keep phase instrumentation opt-in, measure unprofiled chain latency separately, and disclose profiling overhead.
- [Unavailable old logs or mismatched historical revisions] → Retain legacy rows as historical context and use only reproducible runs as v1 acceptance evidence.
- [W12 experiment is external to the Loki source and its disk-cache probe was not adopted] → Record the exact Moriarty/worktree source SHA and label experimental paths; keep chain cache savings as an estimate and do not attribute test-only PK load results to Loki default behavior.
- [Missing shared chain fixture identity] → Block chain measurements until compat-proof provides a fixture-set ID with canonical public inputs, transcript, and verifier instructions.
- [Target variability] → Let platform owners define target compatibility budgets; perf rows remain informational until a named stable runner and comparable fixture exist.

## Migration Plan

No user data or public API migration is required. Add the harness and evidence publication alongside existing measurements; first run it in report-only mode, review the baseline tuple, then enable the pinned-runner regression decision. Roll back the CI decision to report-only if runner invariants fail, retaining the raw evidence and leaving compatibility gates intact.
